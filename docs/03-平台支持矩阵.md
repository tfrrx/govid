## 2. 先说清楚「支持」是什么意思

同一个「支持」有三种完全不同的含金量，混在一起谈会误判：

| 层次 | 含义 | 判断依据 | 本项目现状 |
|------|------|---------|-----------|
| **L1 有解析器** | yt-dlp 里有对应的 extractor 代码 | 出现在 `--list-extractors` | 1752 条 |
| **L2 能解析** | 用真实链接跑通，拿到标题与格式列表 | 实测无报错 | 见下表「✅ 解析通过」 |
| **L3 能下载** | 完整走完下载 + 合并 + 出可播放文件 | 端到端验证 | B 站已验证 |

**本项目的对外承诺口径**：只对 **L3** 做承诺；L2 标注「可解析」；L1 标注「理论支持」。

> yt-dlp 的 `Douyin` 提取器报 `Fresh cookies are needed`。这条报错**具有误导性**——真正的原因见 §3.3b，给了 cookie 也没用。所以本项目对抖音另建了一条通道。

#### 3.3b 为什么必须另建通道

抖音自 **2026-09-14** 起给 `aweme/v1/web/aweme/detail` 加上了 `x-secsdk-web-signature` 门禁：

```
HTTP 403  Blocked by ArgusSecurityPlugin Uifid Not Found
```

社区既有结论（`jiji262/douyin-downloader` README、`douyin.wtf` troubleshooting 文档）：

- 这个 403 **与 cookie 无关** —— 带不带 cookie、重试多少次都一样；
- 放行所需的 `x-secsdk-web-signature` **只能由抖音网页内的 SDK 生成**，CLI 的 API 直连请求无法带上；
- 自己手算 `a_bogus` 也不够（实测：签名完全正确仍返回同一个 403，因为 Argus 还要 `UIFID` 设备指纹）。

**本项目的解法**：用一个**全新的、不含任何用户数据的**浏览器上下文打开抖音页面，让抖音自己的 JS 去生成签名，我们只监听页面自身发出的 detail 响应并取走 JSON。之后真正的下载走纯 HTTP 直链（CDN 不校验签名）。

合规边界：
- ❌ 不读取、不导入、不注入用户浏览器的任何 cookie 或登录态；
- ✅ 独立临时 profile，无 cookie / 无 localStorage / 无扩展，cookie 全部由抖音匿名种下；
- 解析阶段开一次浏览器（约 4 秒，结果缓存约 3 小时），下载阶段零浏览器开销。

实现与踩坑详见技术文档 §4.6。

## 6. 环境说明（关键，别误判）

### 6.1 本次实测跑在什么网络里

本次测试运行在 **WorkBuddy 内置沙箱**，其环境变量里注入了代理：

```
HTTP_PROXY=http://127.0.0.1:53817
HTTPS_PROXY=http://127.0.0.1:53817
```

**所以国际站才可达**（YouTube / X / Instagram 均返回 200）。

### 6.2 你自己启动服务时会怎样

你从**系统终端**跑 `./run.sh` 时，是**国内直连**，没有这个代理。结论要分开看：

| 站点类型 | 沙箱内实测 | 你系统终端直连的预期 |
|---------|-----------|-------------------|
| 国内平台（B 站 / 微博 / 网易云…） | ✅ 可达 | ✅ 同样可达 |
| YouTube / X / Instagram 等 | ✅ 可达 | ❌ **大概率不通**（除非你有自己的代理） |

### 6.3 要跑国际站怎么办

在 `.env` 里配上你自己的代理：

```bash
GOVID_PROXY=http://127.0.0.1:7890
```

后端会自动把这个代理传给 yt-dlp。**不配就是直连，国际站会失败。**

### 7.5 常见报错对照

| 报错关键词 | 含义 | 处理 |
|-----------|------|------|
| `Unsupported URL` | 无对应提取器 | 平台不支持 |
| `Fresh cookies are needed` / `Cookies … needed` | 需登录态（**抖音除外**，见 §3.3b） | 导出 cookies.txt（见 §8） |
| `Blocked by ArgusSecurityPlugin` | 抖音风控门禁 | 本项目走独立通道绕过，见 §3.3b |
| `No video formats found` | 提取器跟不上源站 | 升级 yt-dlp，仍失败则放弃 |
| `server reported error -1002` | 源站拒绝（内容被屏蔽/地区限制） | 换链接，或确认内容本身是否可播 |
| `Unable to download JSON metadata` / `Failed to parse JSON` | 源站接口变更 | 升级 yt-dlp |
| `Unexpected response from webpage request` | 反爬 | 升级 yt-dlp 或加 cookie |
| 抖音报「没有可用的浏览器内核」 | 缺 Chrome | 装 Google Chrome，或 `playwright install chromium` |

## 8. 提升成功率的三个动作

1. **升级 yt-dlp**（收益最高）
   本项目以可编辑模式安装本地仓库，升级 = 拉最新代码：
   ```bash
   cd /Users/happy/Project/Python_VideoDownlaoder/govid/yt-dlp && git pull
   ```
   国内平台接口变动频繁，多数「解析失败」在最新版会被修掉。

2. **提供 cookies**（解锁西瓜 / 小红书 / Vimeo）
   > 抖音**不需要**这一步 —— 它走独立通道，且刻意不接触用户 cookie。
   用浏览器插件导出 Netscape 格式 `cookies.txt`，然后在 `.env` 里指定：
   ```bash
   GOVID_COOKIES_FILE=/绝对路径/cookies.txt
   ```
   > 配置项已预留，但**代码里尚未接上**（见技术文档 TD-5）。要用需要先在 `core/media.py` 的 `_base_opts()` 里读取该配置并传给 yt-dlp。

3. **配代理**（解锁国际站）
   见 §6.3。

## 9. 附录：提取器统计口径

```
$ .venv/bin/python -m yt_dlp --list-extractors | wc -l
1752

$ ... | grep -c "CURRENTLY BROKEN"
136

$ ... | grep -v ":" | grep -vc "CURRENTLY BROKEN"
1201          ← 顶级可用站点数
```

**注意数字口径**：1752 是「条目数」，包含子提取器（如 `youtube:tab`、`bilibili:bangumi`）。对外宣传「支持 1800+ 平台」是行业惯用口径（含子项），**本项目文档统一采用 1201 这个更保守的顶级站点数**，避免夸大。

完整清单见 `docs/reference/yt-dlp-extractors-2026-09-21.txt`，国内平台专项清单见 `docs/reference/中国平台提取器清单.txt`。
